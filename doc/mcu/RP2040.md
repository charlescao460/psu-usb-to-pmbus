# RP2040 platform

This document describes the current MCU and board implementation for
`psu-usb-to-pmbus`.

## Supported board

The initial target is the **Adafruit Feather RP2040 with USB Type A Host**. It
provides a USB host connector and a VBUS power switch suitable for connecting the
AX1600i USB interface.

The build selections are:

| CMake variable | Value |
|---|---|
| `PSU_USB_TO_PMBUS_MCU` | `RP2040` |
| `PSU_USB_TO_PMBUS_BOARD` | `ADAFRUIT_FEATHER_RP2040_USB_HOST` |
| Pico SDK board | `adafruit_feather_rp2040_usb_host` |

## Pin assignment

| Function | RP2040 pin | Notes |
|---|---:|---|
| USB host D+ | GPIO16 | Connected to the board's USB-A connector |
| USB host D− | GPIO17 | Connected to the board's USB-A connector |
| USB VBUS enable | GPIO18 | Controls the on-board host power switch |
| PMBus SDA | GPIO2 | I2C1 target data |
| PMBus SCL | GPIO3 | I2C1 target clock |

The PMBus target runs at 100 kHz and defaults to 7-bit address `0x58`.

Use a common ground and external 2.2–4.7 kOhm pull-ups from SDA and SCL to
**3.3 V**. Never pull the I2C pins to 5 V.

## Platform responsibilities

The RP2040 layer under `src/platform/rp2040/` provides:

- TinyUSB host integration through Pico-PIO-USB;
- the asynchronous `UsbTransport` used by PSU backends;
- the I2C1 target and transaction watchdog;
- USB attach, detach, transfer, and recovery callbacks;
- the platform identity used for `MFR_SERIAL`; and
- USB CDC debug output.

The I2C interrupt path talks only to `PmbusServer`. It never invokes USB work or
reads a partially updated PSU state.

## Dependencies

The RP2040 build pins the following versions:

- Pico SDK 2.3.0;
- TinyUSB 0.21.0;
- Pico-PIO-USB commit `675543bcc9baa8170f868ab7ba316d418dbcf41f`;
- Arm Toolchain for Embedded LLVM 22.1.0; and
- Ninja.

CMake FetchContent obtains TinyUSB and Pico-PIO-USB. The Pico SDK is imported
through `cmake/pico_sdk_import.cmake` from the project-local toolchain directory.

The patch at `cmake/patches/pico-pio-usb-clang-crc-inline.patch` is required for
the pinned Pico-PIO-USB revision. It keeps the receive CRC update inline under
Clang; without it, AX1600i bulk-IN acknowledgements can miss their timing window.

## Build and flash

Windows:

```powershell
./scripts/bootstrap-toolchain.ps1
./scripts/build.ps1
```

Linux:

```bash
./scripts/bootstrap-toolchain.sh
./scripts/build.sh
```

The default preset is `rp2040-ax1600i`. Its UF2 output is:

```text
build/rp2040-ax1600i/psu-usb-to-pmbus.uf2
```

To flash, start the Feather in its RP2040 bootloader and copy the UF2 to the
mounted boot volume. The debug CDC serial port may be assigned a different name
after each flash or reconnect; discover it with the operating system or serial
tool instead of embedding a port name in scripts.

## Identity and diagnostics

The firmware converts the RP2040 unique board ID into an uppercase 16-digit
string and exposes it as PMBus `MFR_SERIAL`. PSU backends must preserve this field
when publishing a new telemetry snapshot.

The normal build logs USB state, PSU polling state, selected telemetry, and
transport diagnostics according to `PSU_USB_TO_PMBUS_LOG_LEVEL`. The
`rp2040-ax1600i-scan` preset additionally enables the AX1600i read-only register
scanner.

## Adding another RP2040 board

A board port should keep the RP2040 transport implementation when possible and
provide only the board-specific SDK selection and pin definitions. Confirm:

1. host-capable USB wiring and a safe VBUS power source;
2. PIO pin requirements and timing;
3. an I2C peripheral that supports target mode;
4. 3.3 V-compatible pull-ups and a common ground;
5. a stable hardware identifier; and
6. detach, reconnect, stale-snapshot, and PMBus watchdog behavior.

For a different MCU family, follow the broader [porting workflow](../../README.md#porting)
and implement the platform interfaces without adding MCU dependencies to the PSU
or PMBus layers.
